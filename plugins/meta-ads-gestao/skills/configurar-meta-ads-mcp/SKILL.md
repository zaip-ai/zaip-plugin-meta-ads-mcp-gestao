# Instalar o Meta Ads MCP – Gestão

Ao receber “instale esse plugin https://github.com/zaip-ai/zaip-plugin-meta-ads-mcp-gestao”, faça os passos abaixo com as ferramentas do cliente em que a pessoa quer usar os anúncios. Use o GitHub ou o catálogo nativo para ler os arquivos. Não abra uma aba do ChatGPT, não peça acesso ao navegador e não peça novo login no ChatGPT. A autorização da Meta é pessoal e pode abrir uma página que a própria pessoa controla.

## No Codex local

1. Trabalhe no perfil local persistente de quem fez o pedido. Confira `codex plugin marketplace list --json` e a origem do catálogo `zaip-meta-ads-plugins`, se existir. Reutilize o catálogo deste repositório. Se o nome já apontar para outra origem, informe o conflito e preserve a configuração existente.
2. Se faltar o catálogo, execute `codex plugin marketplace add https://github.com/zaip-ai/zaip-plugin-meta-ads-mcp-gestao --ref main`. Se o catálogo Git correto já existir, atualize apenas esse catálogo com `codex plugin marketplace upgrade zaip-meta-ads-plugins`. Se for uma fonte local legítima, confira a versão disponível nessa pasta.
3. Consulte `codex plugin list --marketplace zaip-meta-ads-plugins --available --json`. Identifique `meta-ads-gestao` e sua versão. Se faltar a instalação da versão disponível, execute `codex plugin add meta-ads-gestao@zaip-meta-ads-plugins --json`. Verifique a instalação com `codex plugin list --marketplace zaip-meta-ads-plugins --json`. Se o plugin já estiver instalado e habilitado na versão pretendida, prossiga diretamente. Se aparecer desativado, use a opção de habilitar do cliente. Se o chat ainda não carregar as ferramentas após a instalação, oriente abrir uma nova conversa no Codex.
4. Use o fluxo **Conectar** ou de autenticação do MCP oferecido pelo cliente. Se o Codex expuser o servidor em `codex mcp list`, confira a identidade e quando aparecer `meta-ads` com a URL oficial e o estado `not_logged_in`, execute `codex mcp login meta-ads` e deixe a pessoa autorizar a Meta. Se o cliente usar outro nome para esse mesmo servidor, use o nome que ele listou. Se o servidor empacotado só aparecer no painel do plugin, siga a conexão por ali. Não cadastre um segundo servidor para tentar corrigir autenticação nem peça para a pessoa executar comandos.

## No Dot ou ChatGPT Work

1. Procure **Meta Ads MCP – Gestão** nos plugins e ferramentas acessíveis na conta e no workspace atuais. Confirme a origem do conector pelos detalhes disponíveis e o endereço oficial `https://mcp.facebook.com/ads`. Se houver homônimos de origem incerta, esclareça qual é o correto. Preserve conexões existentes.
2. Se o conector já estiver disponível, reutilize-o. Se o catálogo nativo oferecer a instalação, apresente o cartão ou o link de instalação que ele realmente devolver para esse workspace. A pessoa escolhe **Instalar** e **Conectar** quando esses botões aparecerem. Se já estiver conectado, avance para a consulta de leitura.
3. Se o cliente oferecer uma operação nativa para registrar um **servidor MCP remoto** naquele workspace e o perfil tiver permissão, use o nome **Meta Ads MCP – Gestão**, a URL HTTPS acima, o transporte Streamable HTTP e OAuth com registro dinâmico de cliente (DCR) quando a descoberta oferecer. Use o ícone do pacote se houver campo para isso. Confira se o resultado disponibilizou o servidor, a instalação e o fluxo de conexão. Um cartão de sugestão, uma skill carregada ou um pacote privado criado, por si só, não comprovam essas etapas.
4. Se a ferramenta só permitir buscar ou sugerir plugins e não encontrar o conector, explique o ponto exato que falta. Não instale o pacote em um terminal temporário do Dot como substituto da instalação no workspace. Um link restrito ou ZIP exportado de outra conta não transfere o registro nem o OAuth. Para seguir **sem Computer Use**, oriente a pessoa ou o administrador a abrir **Plugins → Pessoal**, procurar uma cópia autorizada e, se estiver ausente, usar **Plugins → + → Adicionar servidor MCP personalizado** com os dados do passo 3. Em **Escolher ícone**, selecione o PNG fornecido. Revise o aviso e use **Criar como plugin → Instalar → Conectar** conforme os botões disponíveis. Se faltar o **+**, peça ao administrador para verificar **Create plugins with MCPs** ou liberar um conector já aprovado. Só ofereça acompanhamento por Computer Use se houver uma etapa web pendente e a pessoa quiser ajuda para os cliques. Se a pessoa escolher essa alternativa, peça que invoque `$configurar-meta-ads-no-chatgpt` para retomar na etapa pendente.

## Autorizar e testar no cliente de destino

- Deixe a pessoa escolher os ativos e concluir o OAuth na tela oficial da Meta. Nunca solicite senha, código, token ou segredo no chat. Para leitura, confira `ads_read` e `ads_mcp_management` quando oferecidos. Para gerir campanhas, confira também `ads_management`. Mostre os escopos reais antes do consentimento e respeite a escolha da pessoa.
- Se a pessoa quiser acesso ampliado e a Meta oferecer, explique quais escopos correspondem ao uso pretendido: `business_management` para o portfólio empresarial, `catalog_management` para catálogos, `pages_show_list` e `pages_manage_ads` para Páginas e anúncios vinculados, `instagram_basic` para perfil e mídias, `facebook_branded_content_ads_brand` e `instagram_branded_content_ads_brand` para anúncios de parceria. Não fixe IDs, empresas ou ativos.
- Depois do OAuth, liste as contas acessíveis. Se a lista estiver vazia, informe e pare. Se houver várias, pergunte qual usar e espere a resposta. Consulte os últimos sete dias na conta escolhida e informe datas, moeda e métricas retornadas. Diferencie um período sem dados de uma consulta que falhou. Examine quais ações de gestão aparecem na lista de ferramentas, sem executá-las.
- Informe onde o pacote foi instalado, se a autorização foi concluída e qual consulta funcionou naquele cliente. Se faltou uma etapa, indique qual e como retomá-la. Em usos futuros, apresente a conta, o ativo e a alteração proposta e aguarde confirmação explícita antes de cada criação, edição, publicação, ativação, mudança de orçamento ou exclusão.
